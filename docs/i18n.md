# 国际化约定

## 注册与命名

`src/i18n/index.ts` 的 `locales` 是语言注册表。首版支持 `zh-CN`、`en`；不支持的语言回退到 `zh-CN`。使用标准语言标签。界面中用语言原名展示选项。

文案按 `app`、`library`、`sites`、`admin`、`common`、`domain` 分 namespace。JSON key 表达含义，不以原文作为 key。类型扩展 `i18next.d.ts` 从中文资源推导有效 key，拼错 key 会导致类型检查失败。

组件使用 `useAppTranslation()` 订阅语言变化，再调用 `t('namespace:key', { name, count })`。非 React 纯函数使用 `i18n` 导出的 `t`；不要在模块加载时把翻译计算成不可变字符串。领域元数据使用 getter，在读取时解析当前语言。

完整句子必须是一个消息，不能拼接几个翻译片段。插值用 `count`、`name`、`collection` 等明确名称。数量消息使用 i18next `_one` / `_other` 等 CLDR 复数形式。React 会转义字符串，禁止把翻译结果直接写入 `dangerouslySetInnerHTML`。

## 添加语言

1. 复制现有语言下全部 namespace JSON，翻译并保留 key、插值参数的语义。为目标语言添加所需复数形式。
2. 在 `locales` 注册语言代码、原生名称、方向及资源。语言选择器自动生成选项；页面组件不写语言分支。
3. 用 `Intl` 格式化日期、时间和数字。当前设计中的中文日期空格保留在格式化边界，不能散落到页面中。
4. 运行单元测试和浏览器测试。检查器会归一化复数 key，并按目标语言的 CLDR 分类要求完整的复数形式。
5. 检查长文案、窄屏、键盘操作；如果新增 RTL 语言，还要审查原设计中的物理左右位置与方向图标。当前首版验收范围是中文和英文，不能只改 `dir` 就视为已完成 RTL。
6. Media Chrome 控件使用同一标准语言代码；在 `components/media/media-player.tsx` 注册新语言的官方字典或补充字典。当前已加载中文，英文使用组件内置字典。周边媒体文案仍归 library namespace。

## 界面语言与内容语言

文章标题、正文、合集名称、人工标签是用户内容，不随界面语言翻译。未改名的内置标签类型按稳定 ID 本地化；用户自定义或改名后保持原文。

保存日期用 ISO 日期，站点检测时间用带时区的 ISO 时间；费用、内容语言等使用稳定代码。在展示边界转成对应语言，不用中文文案充当系统枚举或时间存储格式。

当前演示时钟固定在设计稿的 2026-10-12，以保证概览和时间线可复现；接入真实数据时通过同一领域边界替换时钟。

## 状态

保存的选择优先于浏览器语言，存储不可用时仍可切换。切换同步更新 `html.lang` 和 `html.dir`，不会重建业务数据或清空选择。日期和文案在同一次语言切换后更新。

P1 的 ai_label、分类定义、别名都是用户内容，不随界面语言切换。变化类别使用固定英文枚举，界面在 admin namespace 翻译。未知/复查计数使用命名插值与复数规则。
